# QQ集成 (qq_auto_reply)

通过 OneBot v11（正向/反向 WebSocket，兼容 SnowLuma / NapCat / LLOneBot / go-cqhttp / Lagrange 等任意 OneBot 后端）或 QQ 官方开放平台接入 QQ 的完整机器人集成插件。

- **双通道接入**：OneBot v11 泛用连接（正向/反向）+ QQ 官方开放平台（API v2 能力面，
  见「官方机器人能做什么」）
- **多群注意力管理**：群间注意力竞争、焦点切换、回溯补回
- **接话判定（谁在跟谁说话）**：@你 / 引用你 / 引用别人 / @别人 / 叫你的名字 / 她刚说完的
  第一条 —— 明确在跟别人说话时不抢话，判据同时进打分、门控与提示词
- **动态回复缓冲**：多条缓冲汇总、发送门控自缓冲、频率软提示
- **多模态输出**：文本、语音、图片、表情包、戳一戳、键盘
- **文件内容读取**：文本 / VLM 图片描述
- **提示词编辑**：运行时动态修改系统提示词与场景模板

## 私聊与群聊的记忆方向

- **私聊 → 群聊**：核心记忆与 `recall_memory` 可只读当前真实发言人的私聊记忆。
  管理员使用原有主人记忆库；普通/受信任用户使用自己的 `participant` 记忆域。
- **群聊记忆 → 私聊不开放**：私聊不检索群或群成员记忆。
  存储仍独立，群聊结算不会因为只读共享而写入私聊域。
- **活跃会话信息保留**：开启 `allow_cross_group_context` 时，私聊仍可注入群号、对象称呼、权限等会话元数据；
  这不包含群聊天记录或长期记忆，关闭开关后不再注入。
- 沿用授权开关：须开启 `group_memory_enabled`、`group_member_memory_enabled`；
  非管理员另须开启 `private_participant_memory_enabled`。接收消息后才开启，不追溯授权该轮。
- 不读取旁观者、最近其他发言人的私聊记忆；合并、主动发言、异步任务回投等合成轮次不借用名义发送者身份。
  权限或记忆开关在读取、生成或投递途中撤销时，相关内容/草稿会被丢弃。
- 这是后续读取路径的隔离，不迁移或删除既有记录；用户主动发送/转发到私聊的内容仍属于该私聊已收到的消息。

## 语音回复：复用本体 TTS，无需修改本体

优先调用本体 `POST /api/speech/synthesize`；仅在接口返回 **404/405** 时，插件在自身进程内调用已安装本体的 TTS 调度及音频转换组件，生成 WAV 后缓存并发送 QQ 语音。

- 插件不维护 GPT-SoVITS（GSV）、百炼或其他供应商的独立协议分支，不保存第二套 API Key，也不自行解释 `voice_id`。
- 当前角色、音色、供应商及密钥选择均沿用本体规则；兼容范围取决于已安装本体提供的 worker 和完整音频完成信号，不代表任意第三方 API 都可直接接入。
- 使用独立合成队列，不开启桌面对话、不向桌面播放、不写入桌面对话记录。
- **仅需更新并重新加载 QQ 插件，无需修改、重编译或重启本体。** 若本体缺少可复用组件，会明确报错并按原有设置降级为文字。
- 接口繁忙、超时、连接失败或返回无效音频时不启动兼容路径，避免重复合成；单条最多 2000 字符、WAV 不超过 16 MiB。
- 保留通道能力检查及语音失败回退文字开关；未收到完整音频完成信号时不发送残缺音频，尚未退出的 worker 会阻止后续合成，避免持续创建线程。
- 验证包含本体路由与模拟 worker 的离线测试，不等同于各供应商真实网络合成或 QQ 实际收听验证。

## 官方机器人能做什么（v0.15.7 起）

官方机器人（连接方式选「QQ 官方开放平台」）过去被实现得很窄：只收 @ 消息、发不了语音、
撤回和群成员查询是空壳。下面这张表按 `bot.q.qq.com/wiki/develop/api-v2/` 的能力口径写，
**左列是现在能用的，右列是平台本身没有的**（不是"还没做"）。

| 能用 | 说明 |
|---|---|
| 全量群消息 | 平台上把该群的接收范围设成 `all` 后，`GROUP_MESSAGE_CREATE` 会推过来，接话判定与多群注意力竞争随之自动生效；范围、机器人身份（`bot_state`）可在面板里查 |
| 文本 / Markdown / 图文卡片 | 卡片走 `msg_type=8`（v2 发送侧已无 ark） |
| 图片 / **语音** / 视频 / 文件 | 同一个上传接口，只差 `file_type`；语音支持 silk/mp3/wav，TTS 结果在官方通道也能发出去了 |
| 引用回复 | 被动回复用 `msg_id`，可见引用用平台给的 `REFIDX_` 令牌；两者分开，缺令牌时只做被动回复 |
| @ 成员 / @ 全体 | 用文档现行标签 `<qqbot-at-user id />`；@ 全体要求机器人是该群管理员，每群每自然日 1 次 |
| 撤回 | 发出去 2 分钟内；撤别人的消息要求管理员 |
| 按钮键盘 | 指令按钮，点击后填进输入框；回调按钮 3 秒内自动应答 |
| 「正在输入」提示 | 仅单聊（`msg_type=6`） |
| 群资料 / 成员名册 / 成员信息 | 按名字找人、判断谁是管理员都靠它 |
| 禁言 / 移出 / 黑名单 / 入群申请与审批 | 全部要求机器人在该群是管理员；权限由平台判定，不本地猜测 |
| 自定义菜单 / 指令面板 / 加好友分享链接 | 官方接口直通 |
| 入站语音的自动文字 | 平台给的 `asr_refer_text` 直接进正文，不需要额外 STT |
| 事件 | 入群/退群、单聊与群聊的收信开关、好友增删、订阅授权状态、全量群消息 |
| 入群申请 | **主动拉取**（`join_requests` + `approve_join`）；申请事件本身要另外的订阅位 |

**事件订阅位由连接器定死**（Identify 里 `(1<<25) GROUP_AND_C2C_EVENT | (1<<12) DIRECT_MESSAGE`）。
两类事件默认收不到，而且**不是忘了写**：

- 群成员进出、入群申请事件要 `GROUP_MEMBER_EVENT (1<<24)`；按钮回调与快捷菜单回调要
  `INTERACTION (1<<26)`。这两位在开放平台是**申请制**，文档明确写着"传了无权限的 intents，
  websocket 会报错并直接关闭连接"。擅自加上去 = 没申请过的机器人连不上。
- 所以本层不动 Identify。按钮和菜单项一律用**指令型**（点击后把内容填进输入框、当普通消息
  发回来），这条路不需要回调权限，功能照样成立。
- 入口仍提供 `respond_interaction`：宿主哪天订上那一位，插件侧不用再改。

平台没有的（会明确报错，不再静默返回空）：**戳一戳**、**给群聊或单聊消息贴表情表态**
（表情表态只有频道消息有）、**读取历史消息**（平台不推就不知道，只能用插件自己的积压）、
**合并转发**、群公告/精华/群文件系统。

新增入口「官方机器人：接口能力」（`open_platform`）：先 `action=capabilities` 看当前连接
实际支持什么，其余动作按说明调用；`action=api` 可按官方接口索引直通任意表内接口。

## v0.15.11 稳定版（2026-11-13）

- 官方机器人新增一层**能力面提示词**（提示词层 `capabilities_open_platform`，可在提示词编辑器里改）。
  清单不是写死的，是每轮按当前连接的能力旗标、当前配置与已授权的插件分档**现场生成**：
  能发什么（语音 / 文件 / 视频 / 图文卡片 / 按钮 / 引用 / 撤回）、平台的硬限制
  （被动窗口、每条消息最多回复 5 条、@ 全体要管理员且每日 1 次、用户可关主动推送）、
  以及**做不到的三件事**（戳一戳、给群或单聊消息贴表情、翻历史消息）——
  明说做不到的原因是：不写她就会答应"下次戳你一下"。
- 写法参考 MaiBot 的 `planner_reply_capabilities`：只列"这一轮真的在范围内"的能力，
  并声明「能用不等于一定发得出去，以实际结果为准」。分段、主动搭话、互动召回、
  管理员身份都会改变清单内容，所以静态清单必然与运行时漂移。
- 外部能力（数据库 `plugin_database`、图像记忆库 `neko_image_embed`）在**已授权**时才写进提示词，
  并带上真机核对过的边界：图像记忆库的 `img_send` 只推进本体聊天、发不进 QQ。
  没授权就一个字不写 —— 写一个调不到的能力名，她会去调然后失败。
- 顺带修两处事实：`<ark>` 在官方平台是按**图文卡片**发（不是 ark），新增 `<record>` 语音的说明。
- OneBot/NapCat 通道**不注入**这一段（那侧能力不一样，写进来就是假话），已有测试钉住。
- 新增测试 12 项（能力清单跟随旗标/配置、做不到的三件事、外部能力只列授权过的、
  桥坏了不影响主清单、层表登记与占位符、注入只在官方通道、主题不重复第三遍）。

## v0.15.10 稳定版（2026-11-13）

- **修好一条从来没通过的路**：主动原文直发（别的插件让猫娘说一句）私聊那条调的是

- 面板新增「记忆的外部支撑」说明：数据库与图像记忆库是本体里的另两个插件

## 配置

### 回复风格预设

OneBot 控制台的 **配置 → 参数** 首先选择回复风格，点击「保存设置」后生效：

- **快速回复 · 不休眠**：关闭群聊/私聊缓冲、自动休眠、注意力回落和每次回复的注意力消耗；仍遵守接话资格、权限及安全检查，不保证每条都回复。
- **均衡 · 现有默认参数**：使用原有默认回复节奏。
- **低频长驻**：群聊/私聊收集窗口分别为 10 秒/3 秒，频率软提示参考为 180 秒内 2 条；注意力回落更慢，静默休眠延长至 2 小时。频率提示不等于硬性限流。
- **自定义**：展开注意力、休眠、缓冲等细调项。切换预设再切回自定义，会恢复本次尚未保存的自定义编辑。

旧配置若已调整预设所管理的参数，会显示为「自定义」，不会因打开页面或升级而被覆盖。预设不改变记忆/跨群上下文授权、主动搭话、连接或出站安全开关。记忆和主动搭话仍独立配置。

### 积压管理与桌面提醒

QQ 集成保留群消息积压记录、摘要/详情查看、标记已审和群内回溯处理，
但不再自动把积压摘要推送给桌面猫娘，也不做静默上下文注入。
桌面重要消息提醒由 QQ 助手负责；普通群原有的 QQ 转发逻辑不受影响。
旧配置中的 `backlog_notify_cooldown_seconds` 和 `backlog_issue_notify_threshold`
仅为兼容而保留，不再生效；无需删除已有积压数据。

### 按群开启表情包收集

在 OneBot／开放平台管理页的群列表中，每个群都有 **允许自动收集表情包** 开关。
新群及没有配置该字段的已有群均默认关闭；只加入信任群并不会自动同意存图。
开启后仍受全局 `sticker_collect_policy` 约束，`any` 也不能绕过群开关。
关闭后，该群的表情包和普通图片均不会通过收集工具或图库自动收图入口新增保存，
包括未带表情包标记的图片；下载或等待入库期间关闭开关，也会在写入前重新检查。
正常聊天识图、私聊和手动上传不受这个群开关影响，已有库存不会自动删除。
开关开启须保存成功才生效。

配置存放于 `trusted_groups` 的对应条目，例如：

```json
{"group_id": "123456", "level": "trusted", "sticker_collect_enabled": true}
```

省略或设为 `false` 即关闭；只接受 JSON 布尔值，不把字符串 `"true"` 当成开启。
修改群级别或转发概率不会重置已有的收集开关。

### SnowLuma 手动连接注意（以下根路径行为曾在 v1.14.20 真机验证）

- 正向 WebSocket 请连**根路径**（如 `ws://127.0.0.1:3002/`）：收事件 + 调动作。
  SnowLuma 的 `wsServers` 在 `path: "/"` + `role: "Universal"` 时另有按路径分流的
  语义——`/api` **只能调动作、不推送消息事件**（连上但收不到消息），`/event` 只收事件。
  token 两种携带方式（`?access_token=` 与 `Authorization: Bearer`）都支持。
- `trusted_users` / `trusted_groups` 条目是对象（`{"qq": "123", "level": "trusted"}`）。
  写成字符串数组也能启动（按默认档收录），但面板编辑建议用对象格式。

### 图库与表情包统一管理

- 自动收图、保存表情包和手动上传共用 `sticker.json` 与 `sticker/`；在原有的**表情包管理页**查看图片、删除和管理描述，不再维护第二份图库索引。图库工具、头像工具读取同一份库存，删除后立即不可见。
- 普通聊天图片只作为素材管理，不自动出现在可发送表情目录；通过 `save_sticker` 收藏后才能作为表情使用。私聊/群聊来源作用域保留，群聊普通图片和表情包的自动入库均须开启该群的收集开关（默认关闭）。
- 升级首次启动自动迁移旧 `gallery/index.json`，每条迁移成功后记录进度，完成后归档为 `gallery/index.migrated.json`。旧 `gallery/blobs/` 只作为恢复备份保留，不再作为活动库存，也不会因重启把已删除图片重新导入。来源无法确定的旧收图限制为不可跨会话发送。
- 自动图库收集到达上限后停止新增，不再淘汰用户维护的库存。请在表情包管理页清理；升级不会主动删除旧图片。


### 主动搭话（私聊）：多个定时问候窗口

在 **参数 → 主动搭话（私聊）** 中启用定时问候并添加时间段，最多 12 个，每段可单独启停、删除：

- **参考样例问候**：填写一句样例，由当前猫娘按人设和聊天上下文自然改写；留空则按时间问候。
- **搜索话题**：填写搜索方向，复用本轮已启用且授权给 QQ 的搜索工具。
- **视频平台找话题**：填写平台或兴趣方向，使用已授权的视频查询/搜索工具寻找可聊内容。提示词要求依据真实结果，不把读取标题描述说成看过完整视频；工具不可用或查询无结果时退回普通/样例问候。

时间使用本机时区，结束时间早于开始时间表示跨零点（例如 `23:30–00:30`）。**QQ 插件在时间段内连接就绪时触发；提前在线则在段内随机一个时间触发**（不是监听管理员个人 QQ 的在线状态）。随机计划保存到磁盘，不会每轮重抽；段内才启用/新增的时间段从剩余时间中随机。上线检测约每 5 秒一次，随机目标临近时单独唤醒，不依赖群维护的 60 秒轮询。两种触发合计每段按开始日期最多尝试一次，错过不补发，重连/重启不重复已尝试的问候；修改同一段的内容不会重发已尝试的当日问候。所有时间段与其他主动消息共用每日上限、最小间隔、静音和近期聊天限制，因此添加时间段不会提高发送额度。受限时仅在当前时间段内等待，过段即放弃，不补发。默认保持关闭，不自动授予工具权限；定时问候只发给管理员私聊。


### 搜索／视频话题的链接追问

管理员私聊中，猫娘通过已授权的搜索／视频插件找话题后，可以继续问“发我看看”“链接呢”“文章出处在哪”。
插件会从工具真实结果中提取标题、简短摘要和公开原链接；工具结果行清理后，来源仍可在后续轮次使用。

- 话题消息**确认发送成功后**才记入来源备忘，覆盖主动搭话、普通私聊、私聊缓冲投递和异步工具回投。
- 来源保存在插件数据目录的 `topic_sources.json`，重启可恢复；最多保留最近 **4 个话题**，有效期 **7 天**，每个话题最多 **8 条来源**。
- 明确对应时要求回复原链接，不重新搜索来替换；多个候选无法对应时先确认是哪条。
- 当轮没有有效来源或记录已过期时，要求说明未保留链接，不编造、不拿更早的话题顶替；重新搜索需明确说明。
- 只用于当前管理员的持久私聊，不注入群聊、其他用户或临时会话；不保存完整工具结果、搜索参数或带凭据的链接。
- 不额外授予工具权限，不自动打开定时问候，也不代表猫娘已看过完整视频或确认链接仍可访问。

## QQ 视频概况联动

支持搭配 `video_reader` 的 `prepare_for_qq` 入口，在原 QQ 私聊/群聊中回复视频概况。
沿用 `qq_open_plugin_tools` 白名单、通道与实时名册权限，不自动授权。旧版视频插件没有此入口时不挂载其桌面分析入口。

- 每轮仅处理一个公开视频链接；只挂载 `prepare_for_qq`，禁止通过此桥选择会向桌面推送的 `analyze` 等入口。
- 抽帧调用单独允许 300 秒，视频视觉分析单独允许 65 秒；其它插件保留原超时。只有挂载视频工具的会话轮次才增加等待预算。
- 图片经完整性与尺寸校验后，通过宿主 `vision` 配置和独立临时客户端处理（兼容宿主免费视觉配置，无需插件模型槽）；只把文字概况交回 QQ 对话模型。
- 不修改 `_pick_vlm_config`，不修改普通图片/表情包的模型选择，不切换主 QQ 会话模型，不向记忆和工具文本写入 base64。
- 下载和视觉处理后重新检查权限；失败不编造观看结论，取消不自动重试或补发，发送仍由原 QQ 回复链路管理。
- 当前只分析抽样画面，不分析声音；默认最多看 300 秒，长视频需明确范围并由用户下一轮要求继续。

使用示例：管理员私聊发送“帮我看这个视频并总结：https://www.bilibili.com/video/BV18W4b6eE8Q/”。
在群聊使用时仍需满足该群原本的注意力、权限与触发规则。
