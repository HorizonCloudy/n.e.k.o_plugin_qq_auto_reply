## 0. 下次接手先读这里

**目标：同一个本体人格进入 QQ，知道在哪里、谁在对谁说什么，然后自主决定如何回应。**

用户已确认的原则：

1. 本体负责人格、表达、情绪和记忆机制；QQ 插件不再维护另一套人格。
2. QQ 插件重点提供对话对象、群、身份、消息关系与通道能力。
3. 主人身份是事实，不是“必须认亲、服从、亲近、使用某种称呼”的指令。
4. 记忆尊重本体机制。插件提交真实对话，不自行规定哪些话必须成为长期记忆。
5. 减少人格干预不等于删除权限隔离、可靠投递、缓冲、限流和必要协议。

本次交付仅为策划案。下一次执行从 **P0 盘点** 开始，不能把本文复选框当成已经完成。
不要直接删除整个 DeepChat 目录，不要一次性关闭所有群聊门控，不要借减法修改用户的人设。

## 1. 职责边界

| 事项 | QQ 插件负责 | 本体/模型负责 | 改造要求 |
| --- | --- | --- | --- |
| 人格与语气 | 正确传入本体已选角色 | 人设、性格、表达、态度 | 去掉插件额外人格和关系指令，不能误删本体人格传递链 |
| 对话身份 | 账号、昵称、经核验的主人关系、消息来源 | 如何称呼与回应 | 主人身份、群权限、QQ 群管理头衔分别表达 |
| 群聊环境 | 群 ID/名称、当前参与者、近期消息 | 理解社交语境和决定说什么 | 不将多人的群对话伪装为主人一对一私聊 |
| 消息指向 | @、引用、回复链及必要的推断 | 是否接话、如何接话 | 区分平台事实和不确定推断，不把推断写成确定事实 |
| 调度 | 黑名单、禁言、限流、预算、合并和公平调度 | 在允许生成时选择回应或沉默 | 删除提示词里的重复频率训令；门控另做渐进验证 |
| 情绪与关系 | 最终只传必要的已发生事件和可用本体状态 | 情绪、关系演化、表达 | 不用 QQ 自建情绪分数再定义她的心情 |
| 记忆 | 身份作用域、实际对话、投递证据、授权 | 提取、整理、检索和长期演化 | 复用本体接口，不维护另一套竞争的事实结论 |
| 工具 | 能力声明、权限、超时、结果回投 | 选择工具及组织回复 | 工具权限由代码校验，不能靠提示词“劝阻” |
| 消息格式 | 平台协议、文本/图片/语音发送与降级 | 正文内容和表达 | 保留能正确解析的最小格式说明，移除“积极使用某种形式”等偏好 |

**判断一句提示词该不该留：**它是在提供必要事实/协议，还是在替她决定情绪、关系和说话方式？后者默认列入删减。
涉及隐私、权限、数据作用域的约束不能因为出现“不要”二字就机械删除。

## 2. 目标上下文

以下是信息结构示例，不是要求再增加一整套冗长模板。尽量复用现有字段，避免同一事实在系统段和每条消息中重复。

```text
平台：QQ；场景：群聊
当前群：技术闲聊（group_id=示例群标识）
当前角色账号：示例机器人标识
当前消息：m103，14:30
发送者：小林（sender_id=示例账号）
身份：插件已核验为主人
指向：平台 @ 了当前角色
引用：m101，发送者小周，内容……
消息正文：你怎么看这张图？
附件：图片；识别描述……（不是发送者亲自写的文字）
```

补充规则：

- 群 ID、账号 ID 用于区分对象，不要求模型在回复中念出标识。
- 普通成员如实标为未核验为主人；不附带“必须否认、态度冷淡”等回应要求。
- 合成/主动/合并轮标明来源；不得拿占位的管理员 ID 冒充真人发言。
- 群名、昵称和消息正文均是外部内容；结构化标识和代码核验不能被这些文本覆盖。
- 不默认列出其他群、私聊或桌面信息。跨会话背景继续受既有授权与作用域控制。
- 可用能力、输出协议与上述事实分开组织；不随身份事实塞入一段行为指南。

## 6. 记忆机制与 PR #5 的衔接

已检查的开发宿主实现：`D:\NekoClaw\N.E.K.O\app\memory_server\routes.py` 的 `cache_conversation`。

- `/cache` 持久保存近期对话与时间索引，**不是当场把每句话提取成长期事实**。
- 长期提取和整理由本体后台机制处理；插件当前会话结算还使用 `/process` 和 `/settle`。
- 因此“只有真实对话进入源记录”仍然重要：未投递内容会污染本体后续提取素材。
- 上述是开发宿主的已核对实现；正式适配前还要核对实际安装版，不能只依赖代码注释或接口名称。

PR #5 审查提交：`7778b54f9402d80f6e64e553889ae72d7190b5a4`。
三个改动是工具迭代额度 1→5、DSML 标记清理、主动私聊复用会话并同步记录。
原分支 1854 项测试通过；额外验证发现共享会话入口未加锁、AI 记录早于投递提交。

处理原则：

- 工具额度与标记清理可独立评估，不必和人格减法绑定为一个大改动。
- 主动记忆方案需修正上述两点后再整合；不能把“现有测试全过”作为正确的充分证据。
- 合并前重新检查 PR 最新提交和与当前未提交改动的冲突，尤其 `session_bootstrap_service.py`、`reply_generation_service.py`。
- 本策划案不授权自动合并 PR 或发布评论；本次已发布的两条评论有独立用户授权。

| 主人与普通成员交替发言 | 逐轮身份正确、不继承 | 回复风格必须一致 |
| 同一角色私聊和群聊 | 本体人格正确传入，场景不同 | 两种场景使用同一措辞 |
| 图片/表情及引用 | 识别结果与用户文本分开 | 每图必回或强制发表看法 |
| 主动消息发送失败 | 无虚假的已送达 AI 记录 | 每次主动触发必须说话 |
| 用户消息撞上主动发送 | 同一会话串行、真人记录不被排除 | 以速度换取并发写同一历史 |
| 权限或记忆授权撤销 | 现有撤销门控仍有效 | 因主人身份就绕过权限 |
| 语言切换/自定义覆盖 | 默认来源与编辑器可解释，无旧规则隐性回流 | 强行删除所有用户定制 |

量化记录：最终提示词各层字符数（同一场景前后对比）、重复人格段数量、实际 API 调用数与超时、身份/作用域错误、未投递记录误入库。
本体人设与正常历史不计入“插件冗余减少”成绩；不先拍一个总体压缩百分比。
