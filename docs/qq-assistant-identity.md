# QQ 助手与 QQ 集成的账号身份联动

## 解决的问题

QQ 助手监听的账号和 QQ 集成登录的角色账号不是同一个概念。旧版通知文案把发信人写成“另一个 QQ 用户，既不是主人、也不是你”，因此角色自己的消息也会被错误描述。

## 接口与判断

QQ 集成新增只读 `account_identity` 插件入口，对模型工具候选隐藏，但可通过宿主插件总线调用。它只返回 schema_version、provider、platform、account_scope、available、self_id，不暴露配置、凭据或联系人。只有在线且已核验的 OneBot QQ 用户账号有效；官方机器人 ID 属于不同命名空间，不参与 QQ 号匹配。

QQ 助手使用 `self.plugins.call_entry_json("qq_auto_reply:account_identity", {}, timeout=2.0)` 获取身份，严格校验协议，只按 QQ 号匹配，不按昵称。缓存和重试节流均为 10 秒；离线、超时、旧版插件或错误响应视为身份未知，不把未知身份断言成“不是你”。

## 行为

- 已确认角色账号的消息继续保留在原始历史中，不修改原记录或 is_outgoing。
- 不触发“别人找主人”的提醒，不进入自动代答；缓冲通知和排队代答在处理前复核。
- 摘要、收件箱、最近消息、对象查询返回身份上下文，并把匹配的账号标为“你本人（QQ 集成账号）”。
- 若助手监听的也是角色账号，不把该账号的发送当成人类主人在线的证据。
- 同昵称但不同 QQ 号的用户不受影响；群号不能当作发信人的 QQ 号。
- 不删除或重写此前已经进入宿主对话/记忆的错误提示。

## 维护与验证

QQ 集成源码：本仓库 `account_identity.py` 和 `__init__.py`。
QQ 助手配套源码：宿主工作区 `plugin/plugins/qq_assistant/qq_identity.py`、`__init__.py`、`notifier.py`。需要同时分发两端。

回归覆盖：离线/账号切换/格式校验、缓存过期与并发、同名用户、群号碰撞、历史不变、通知缓冲过滤、代答生成前与发送前拦截。

本机验证只读调用两个插件：集成的 account_identity.self_id 应与助手 assistant_who.identity_context.character_qq_id 一致。测试不用发送 QQ 消息，也不调用模型。配置和聊天历史不应被部署覆盖。

## 2026-11-06：主人账号来源修正

实际部署中 QQ 助手监听主人账号，QQ 集成登录另一个角色账号。此前两端接口报告相同，并不能证明用户使用同一个账号：助手探针错误选取了 `LocalLoginInfoList[0]`（本地保存的账号列表第一项），随后又拒绝真正 `GlobalDataApi` 当前会话的账号更新。

修正后：

- 探针只通过 `GlobalDataApi` 建立/切换当前账号；登录记录列表不认领身份，好友 profile 事件只能更新已匹配账号。
- QQ 助手拒收旧 `login_info` 来源，并忽略旧版身份缓存；历史只在已发送记录的账号唯一时用作回退，不在多个账号之间猜测。
- 新身份缓存记录版本；换号清除旧昵称/UID/头像，部分资料更新不会丢失原账号字段。
- 已知主人身份不再被错误方向标记或旧探针 selfUin 覆盖；角色发出的消息不会刷新主人的活动状态。
- 跨插件提示明确区分主人监听账号和角色账号，不再把“两个接口返回相同”当作用户实际共用账号的证据。

Python 接收端重载插件后生效。JS 探针运行在 QQ 进程内，新源码需要正常退出并重新启动助手所监听的 QQ 才会加载；分发不会强制退出 QQ。接收端兼容保护可在旧探针运行期间拒收错误身份。
