# 群聊图片、表情：理解与回复分离

## 行为

- OneBot 中参与自动聊天的群（`trusted`）：未 @ 她、未引用她的纯图片/表情仅保留解析后的上下文，不单独触发回复。
- 多张图片、QQ 表情、商城表情以及空白文字组合均适用；@ 全体或 @ 别人不等于 @ 她。
- @ 她或引用她时允许进入回复流程，但纯图片不会设置 `force_reply`。这不是保证不回复，最终仍由现有回复流程决定。
- 图片附带真实文字时，点名、关键词、提问和注意力内容信号只看发言人实际输入的文字，不把图片描述当成发言意图。图片描述仍供后续理解和黑名单检查使用。
- 被跳过的纯图片标为已审，避免回溯补回再次触发；不删除上下文，也不触发自动复读。
- 私聊、开放平台以及普通群的转达路径不变。语音、文件、合并转发等复杂消息保留既有行为。

## 原因

此前 VLM 描述会写入 `content`，然后被门控直接用于名字、关键词及回复必要性判断。描述中的名字、问句和较长文本可能让一张表情包被误认为需要回答；正在聊天或管理员优先时也没有纯表情的独立静默规则。

## 验证

`tests/test_media_reply_policy.py` 覆盖原始段/CQ 识别、描述与真实文字区分、热群/管理员/注意力关闭场景、@/引用放行、普通群和私聊兼容、黑名单、已审与复读隔离。真实派发入口测试使用假的 VLM 回调验证描述仍进入 backlog，不产生外部请求。

手动验证：在允许聊天的群里连续发送几张不带文字、不 @ 她的表情，应看到解析及 `passive_media_context` 日志，但不逐张回复；再发「@她 这张图是什么意思？」应正常进入回复流程。历史已积压的消息不做批量清理。
