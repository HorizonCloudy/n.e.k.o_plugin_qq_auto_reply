# 群聊中的主人识别

群访问权限（`trusted` / `normal`）和发言人的用户权限是两种信息。群聊回复的
`permission_level` 仍然表示群访问权限，不能为了识别主人而改成 `admin`，否则可能扩大工具或记忆权限。

真实消息按发送者账号在插件管理员名单中核验身份，不按昵称、群名片、QQ 群主/群管理员头衔、
引用对象、被 @ 的人或消息里的自称识别。接收时与构建提示词时都为管理员，才加入本轮主人确认。
该提示每轮更新，下一位群友不会继承上一位发言人的身份。

群聊身份提示只提供账号核验事实，不要求认亲、特定称呼或回应态度。
是否在回复中提及身份、如何称呼和回应，由模型结合角色设定与当前群聊上下文决定。
群聊使用独立的 `group_attention_prompt_section`，不再加载私聊注意事项里的身份训令；
旧 `attention_prompt_section` 及其自定义覆盖继续用于私聊。

当前沿用插件已有的“管理员/主人”身份语义，不新增另一份主人名单，也不依赖陪伴插件的主人绑定。
身份识别本身不扩大工具权限，也不开放桌面陪伴记录和个人情绪。
私聊记忆现按单向规则供群聊只读使用：仅当前真实发言人、接收时和读取时都有授权，
且群记忆与群成员记忆均开启时，才能读取其私聊记忆；非管理员还须开启私聊成员记忆。
群聊记忆不进入私聊召回或核心记忆；群活跃会话的群号、对象称呼和权限等元数据仍可
按 `allow_cross_group_context` 开关注入私聊，不等于开放群聊天记录或长期记忆。
合并、主动发言、通知等合成轮次不能因为使用了管理员账号作为占位发送者就被当成主人发言。

## 验证

1. 用插件管理员名单中的 QQ 在已授权的群里发言，确认提示词包含主人身份事实；不要求回复必须认亲或使用特定称呼。
2. 换普通群成员发相同问题，或自称主人，不能继承管理员身份。
3. 主人、普通成员交替发言，检查没有把上一轮身份沿用到下一轮。
4. 身份识别不要求模型公开私聊记录；私聊背景访问另由记忆授权门控，其他发言人不得借用。

自动测试：`tests/test_group_owner_identity.py` 覆盖真实上下文构建、群与用户权限分离、
同名冒充、权限撤销/提升期间的等待窗口、合成轮次、共享会话提示更新及私聊行为不变。
