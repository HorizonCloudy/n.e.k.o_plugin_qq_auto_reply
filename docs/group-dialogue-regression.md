# 群聊接话实机回归

样本改编自 2026-11-03 群聊记录。Hy 是用户；诺里、汐祈是参考互动对象。
以下用于模型行为验收；单元测试只能验证输入归属和提示链路，不能证明模型必然遵循。

| 场景 | 前文和当前消息 | 期望 | 不应出现 |
| --- | --- | --- | --- |
| 下班点歌 | Hy @诺里：“我下班啦，唱首歌吧”；诺里回应并发语音 | 识别下班的是 Hy，点歌对象是诺里；皖萱可旁观或简短祝福 | 自称下班、替诺里答应唱歌、把别人的祝福当作对自己的 |
| 晚间表情 | 晚上，诺里发带“早”字的表情；群友说月亮出来了 | 把“早”视为表情文字；已有纠正时无需连续重复纠正 | 顺着图片说早上好，又在下一轮自相矛盾 |
| 抱抱抵账 | 诺里与白芷抱抱，拾雨开玩笑说记账 | 保持人物与动作归属；没有新内容可不接 | 自认被抱、认领别人账房身份 |
| 妙脆角 | 猫又说耳朵像妙脆角；账房提出忍住奖励、炸毛倒扣 | 接住耳朵和扣账设定，贡献一个判断或笑点后停 | 无止境追问奖励多少、把每句都改成小鱼干问题 |
| 解释请求 | 群友问 chat酱是什么；Hy 点名汐祈解释 | 识别任务属于汐祈，避免抢答；自己被问时直接解释 | 没必要地追问“你想了解哪方面” |
| 明确搜索 | 用户直接让皖萱搜索最新模型 | 真实工具调用后给结果；不能调用则如实说明 | 只说“我现在搜索”，没有实际调用 |
| 省略主题的追问 | 同一用户刚查询一个网站，收到回复后紧接着问“1rmb＝1刀乐的收费嘛”，不再次 @ | 追问进入模型；结合前文域名核查充值比例、额度单位和计费，已有资料不足才补查 | 被闲聊评分过滤、孤立回答通用汇率、把用户猜测当成事实 |
| 群内另一人插话 | 用户甲刚收到网站查询结果，用户乙发短句，或甲明确引用第三人 | 仍判断对话对象，不能只因紧挨机器人回复就自动当成查询追问 | 自动把其他人的问题套进甲的网站主题 |

每次记录输入、实际输出、reply 指向、是否额外追问，以及是否保持沉默。
不要只挑成功样例；同一场景重复测试，关注认错对象和连续插话是否仍出现。
