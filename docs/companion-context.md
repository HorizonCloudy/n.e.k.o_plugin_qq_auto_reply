# 只读陪伴增强（实验，默认关闭）

此功能自动为**绑定主人的管理员私聊**补充背景，不要求模型先选择工具，
适用于现有会话生成和直连兜底路径。它不替代 DeepChat，不写回其它插件，
不主动发消息，不根据桌面时长改变好感度。

## 分工

| 来源 | 本次使用 | 明确不使用 |
| --- | --- | --- |
| 永远的陪伴 | 精确绑定角色当前的情绪动作枚举，作为整体背景 | 原因、日记、身体/周期细节、连续情绪数值、修改情绪工具 |
| 她的一天 | 当日查询时刻、已格式化的桌面陪伴时长 | 任意 summary/guidance 文本、等待推断、QQ 在线时长推断 |
| DeepChat | 每个 QQ 用户原有的关系和即时情绪 | 不用外部背景覆盖、叠加或重新评分 |

统一由 `emotion_service.build_emotion_section` 输出。群聊仍只有群状态；
其它用户、合成消息和主动搭话均不读取这些来源。

## 统一插件授权

普通工具和自动背景复用 `qq_open_plugin_tools`，不再分别维护“她的一天开关”和
“永远的陪伴开关”。**授权的是 QQ 使用能力，不是启动来源插件或修改其内部开关。**

1. 在 QQ 的 **插件 → 私有插件上下文：主人绑定** 填入主人 QQ、机器人 QQ、宿主当前角色完整名称，
   点击 **保存绑定并使用插件授权**。主人须已是管理员；这是一次性的私人数据归属绑定。
2. 在现有 **只有管理员可以用** 区域添加插件，即授权普通工具及该插件已适配的只读背景。
   加入“所有人”也包括管理员，但自动背景仍只给绑定主人，不扩散给其它人。
3. 从授权区移除插件，立即停止该来源的自动背景；正在生成/缓冲的依赖草稿也会失效。
   新增授权必须写盘成功才生效，失败不会出现“界面没保存但运行时已经读取”。
4. 来源须正常运行并有可用的只读接口/有效状态；QQ 不会替你启动来源、安装适配器或开启来源自身关闭的功能。
   卡片会标注自动背景能力及接口是否存在。没有有效情绪动作不等于“开心/平静”，不会编造。
5. DeepChat 总开关及片段开关须开启；自动背景仅支持 OneBot，群聊、其它用户、合成/主动消息仍不读取。
   清空三项绑定并保存可全部解绑。

**普通工具仍按授权档位开放，可能包含写操作及其它私人信息。**
主人绑定只保护自动背景，不改变普通工具的原有授权含义。
`get_emotion_snapshot` 不进入 QQ 通用工具候选。

### 不再绑定两种插件的主流程

`plugin_context_providers.py` 维护可信只读适配器注册表：插件 ID、RPC、参数构造及白名单校验。
编排层只负责统一权限、绑定、超时、撤销与单一情绪出口，不再分支判断两个插件。
新增适配器不需要改回复管线。其它插件已经可通过现有工具桥使用；但**并非授权任何插件就
自动把任意返回值注入背景**，新增自动背景需要显式、安全的只读适配。

新配置示例（`enabled` 表示绑定已确认；界面不再提供第二套来源开关）：

```json
{
  "qq_open_plugin_tools": {
    "neko_presence": "admin",
    "forever_companion": "admin"
  },
  "companion_context": {
    "source_mode": "plugin_tools",
    "enabled": true,
    "owner_id": "主人QQ号",
    "bot_id": "机器人QQ号",
    "character": "YUI"
  }
}
```

### 旧配置迁移

没有 `source_mode` 的旧配置保持原独立开关语义，不因升级而擅自开启先前关闭的私人来源。
保存新版绑定后迁移为 `plugin_tools` 模式；旧 `presence_enabled` / `mood_enabled`
字段不再控制来源（即使还保留在磁盘上）。无绑定、无授权的默认配置仍不读取任何背景。

## 永远的陪伴：只读适配

本次按 `forever_companion` **1.4.7** 的源码结构适配，并核对了
`neko_presence` **0.7.0** 的 `presence_today` 返回结构；这不是所有版本的兼容承诺。

检查的 Forever 版本没有适合本用途的现成只读情绪入口：
`get_status` / `dashboard` 会调用 `_supervise_once()`；后者读取 affect 时还可能惰性衰减状态。
因此本实现**不回退调用这些入口**，也不借助情绪工具获取状态。

QQ 仓库提供 `integrations/forever_companion/qq_emotion_snapshot.py`：

1. 先备份你的 Forever 插件代码；将该文件复制到 Forever 的 `mixins/qq_emotion_snapshot.py`。
2. 在 Forever 的 `__init__.py` 其它 mixin 导入附近加入：

   ```python
   from .mixins.qq_emotion_snapshot import QQEmotionSnapshotMixin
   ```

3. 在现有 `ForeverCompanionPlugin` 的基类列表开头加入 `QQEmotionSnapshotMixin,`；
   保留原来的 `@neko_plugin`、`@guard_data_operations` 和所有其它基类：

   ```python
   @neko_plugin
   @guard_data_operations
   class ForeverCompanionPlugin(
       QQEmotionSnapshotMixin,
       BackupMixin,
       # 其余原有基类保持不变
   ):
       ...
   ```

4. 按宿主支持的方式重新加载 Forever 插件。通过它原有正常启动/使用流程载入相应角色。
   本适配**不会**为了读取而载入、创建或修复角色分片。

这是人工安装的可选适配，没有自动修改你的 Forever 安装，也没有向上游提交或发布。
更新 Forever 后需重新确认兼容性；移除该 mixin 不影响 QQ 的普通回复。

固定 RPC：`forever_companion:get_emotion_snapshot`，参数 `{"lanlan":"YUI"}`。
只接受已加载且可信、存储可用、情绪能力已开启、未过期的角色状态。
返回 schema 1，包括 `lanlan / available / enabled / sampled_at / action / expires_at`。
没有可读动作时返回 `available: false`，不编造“开心/平静”。
只复制动作和到期时间，不返回原因和任何档案，也不调用 supervise、ensure_shard、current_affect。

她的一天固定 RPC：`neko_presence:__llm_tool__presence_today`，参数 `{"date":""}`。
这是 SDK 为 LLM 工具登记的实际跨插件入口，不是 `neko_presence:presence_today`。

## 故障与隐私边界

- 两个来源并行读取，每个最多等待 1.2 秒；没有跨轮统计缓存。
  来源未安装、停止、无接口、超时、返回 Err 或结构不合格时，跳过该来源；另一个来源和本地情绪保留。
- 暂停、当天没有记录或日期不匹配，不注入陪伴事实。记录空白不等于用户缺席。
- 原因、summary、guidance 等自由文本不进入提示词；错误内容不写入提示词或日志。
- 构建开始时快照授权，RPC 完成、生成前、生成后、直发及缓冲发送前复核。
  关闭、换绑定、角色/账号不匹配、撤销管理员、关闭 DeepChat 均使当前依赖失效。
  修改配置使旧草稿失效，即使随后改回相同配置也不会复活旧草稿。
- 授权依赖随缓冲合并保留，最长有效 5 分钟；过期或失效的受影响草稿丢弃，不延迟泄露。
- 外部事实只在本轮临时替换的 system prompt 中使用，不进入复用会话的基础 instructions。
  已发送的回复无法撤回；本功能不是聊天记录/已存在宿主记忆的删除工具。
- 普通回复依然遵守原来的记忆策略；本功能不新增外部事实档案或新后台任务。

## 人工验收（不需要发送群消息测试）

1. 撤销全部插件授权或解绑时：普通私聊行为不变，不应发生以上 RPC。
2. 仅授权她的一天：用绑定主人私聊问“今天桌面陪了多久”，应与同一时刻的该插件面板口径一致。
   追问“现在呢”应重新查询，而不是沿用旧统计。
3. 安装 Forever 适配、让它原有功能产生可读动作后在管理员区授权该插件：回答可以自然体现整体背景，
   但不复述日记/原因，不把桌面发生的事归咎于 QQ 用户。
4. 用其它账号、群聊、开放平台或不匹配角色验证不读取；停掉任一来源后普通回复仍可用。
5. 在生成/缓冲等待时撤销插件授权或更改绑定：受影响旧草稿不发送。刷新面板、重启 QQ 插件后确认配置保持。

自动测试使用 RPC/QQ/LLM 替身，覆盖隔离、验证、超时取消、授权撤销、会话恢复、真实临时目录配置落盘和前端保存。
尚未代替双插件安装环境里的真实 QQ 联调。
